# Fox Watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record garden visits overnight and publish a private Fox Watch page with annotated clips, model comparisons, and entry-to-exit arrows.

**Architecture:** The Pi records completed five-minute files and transfers them to the VPS; one hourly Python process detects, cuts, tracks, classifies, annotates, and renders static pages. JSON sidecars and atomic file replacement provide recovery without a database. Caddy listens on localhost behind a named Cloudflare tunnel and email-restricted Access.

**Tech Stack:** Python 3.12+, setuptools, opencv-python-headless, numpy, standard-library urllib, plain pytest, ffmpeg, Bash, systemd, rsync, cron/flock, Caddy, cloudflared, 1Password CLI.

**Spec:** `docs/superpowers/specs/2026-09-28-fox-cam-design.md` — read it fully before implementing; the user's planning constraints override its obsolete Python 3.14-only and `google-genai` dependency sentences.

## Global Constraints

- Python 3.12+ compatible package under `src/foxcam` with `pyproject.toml`; runtime dependencies limited to `opencv-python-headless`, `numpy`, and the standard library; OpenAI-compatible chat calls use `urllib`, with no `google-genai`, `openai`, or `requests` dependency.
- Plain pytest, one small test module per pure-logic unit: events/night assignment, edges, classifier parsing/comparison, and site rendering. Exercise ffmpeg, providers, deployment, and the camera with runnable checks against the actual tools, not mocks or a new test framework.
- Pi: `rob@192.168.17.145`, Raspberry Pi OS Lite 64 bit (Debian 13 Trixie), imx219; VPS: `root@62.238.55.235`, Ubuntu 26.04, 4 CPUs, 8 GB, 50 GB volume at `/data`; Mac is the development and deployment host.
- Capture at 1280x720, 10 frames per second, H.264, five-minute files with UTC timestamp names; fixed exposure and gain remain configurable; fixed local `START_TIME`/`STOP_TIME`; rsync every 15 minutes; recorder restart after 10 seconds; seven-day Pi safety retention.
- `/data/foxcam/{incoming,nights,site,logs}`; evening-date night directories; raw `HH-MM-SS.mp4`, annotated `HH-MM-SS.annotated.mp4`, four `.f0.jpg` through `.f3.jpg` frames, and `.json` sidecars.
- Required sidecar fields: `clip`, `night`, `start_utc`, `duration_s`, `entry_edge`, `exit_edge`, `labels`, `track`, `frames`; labels map model IDs to `{label, confidence}`; track entries are `[frame, x, y, w, h]`; media references are relative basenames. Task 6 adds only `annotation_label` to record the last rendered label/confidence.
- Defaults: `GAP_SECONDS=3`, `PAD_SECONDS=2`, `RETAIN_NIGHTS=180`, `MIN_FREE_GB=10`; calibration starting points: `MIN_BLOB_AREA=100` at scan resolution, `EDGE_MARGIN=80` at full resolution, `START_TIME=19:00`, `STOP_TIME=07:00`, `TZ=Europe/London`. These additional defaults are tuning values, not measured garden settings.
- Allowed species: `fox, hedgehog, cat, badger, rat, mouse, bird, deer, other, none`; failures use `unclassified`; run every configured model and use only `PRIMARY_MODEL` for headline labels and annotations.
- One `/etc/foxcam.env`; `.envrc` loads only the 1Password service account token; local API checks use `op run --env-file=.env.tpl -- .venv/bin/python tests/check_classifiers.py`; references are `op://foxwatch/nous/secret`, `op://foxwatch/deepinfra/api-key`, `op://foxwatch/together/api-key`. No keys in committed files, command arguments, logs, or the parent shell environment.
- Hourly `flock -n`; refuse processing below `MIN_FREE_GB`; remove source files once every event's cut and sidecar exist; retain annotated clips, frames, and sidecars when raw clips expire.
- Site title `Fox Watch`, hostname `foxwatch.cynexia.com`, Caddy `127.0.0.1:8080`, Cloudflare Access restricted to the user's email; public inbound exposure remains SSH only and existing Fail2ban remains intact.
- No sunset calculations, ground-plane calibration, real-time alerts, on-Pi detection, compression project, multiple cameras, database, SpeciesNet implementation, provider SDKs, or speculative plugin interfaces. Keep prose lines unwrapped.

## Review Focus

- A crash after one cut or during JSON/video output must preserve the source or enough durable work to resume without duplicate visits or lost clips; Task 6 exercises partial work and repeated runs.
- UTC files around midnight and the Europe/London DST change must belong to the evening's night without colliding filenames; Task 1 pins night assignment and Task 7 checks the actual timer schedule.
- Provider HTTP failures, malformed JSON, non-finite confidence, and an unavailable primary model must remain visibly unclassified and retryable without replacing successful comparison labels; Tasks 4 and 6 exercise these cases.
- Recorder termination must not expose unfinished MP4s; failed rsync preserves recordings within the seven-day retention window while cleanup removes older recordings; Task 7 exercises termination and an unreachable transfer destination.
- An absent data mount, an installer rerun, or a direct media URL must not delete root-disk data, destroy existing nights, or bypass Access; Tasks 8 and 9 check these boundaries before enabling automation.
